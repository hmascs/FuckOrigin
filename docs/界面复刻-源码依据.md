## 3. 与任务要求的一处有意差异

要求「不按应用分类，而按功能分类」：所以首页列表的每一项是**功能域**（性能与温控 / 游戏与侧边栏 /
界面与交互 / 系统更新与云控 / 后台与功耗 / 通知与权限 / 原子通知与原子岛 / 设备与调试），
点进去才是该域下的功能条目（带开关）。HyperCeiler 的第一层是应用作用域（`android` / `com.android.camera`…），
我们把它替换成功能域，其余层级（分组标题 + 卡片组 + 行 + 底部三标签）保持一致。

## 4. 为什么没有直接依赖 `fan.miuix`

- HyperCeiler 的 `gradle/libs.versions.toml` 使用 `fan.miuix:core / appcompat / basewidget / cardview / navigator / nestedheader / bottomsheet / animation / folme`，版本 `1.0.13.0`；
- 这些构件发布在 **GitHub Packages**：`settings.gradle.kts` 里强制读取 `gpr.user` / `gpr.key`（否则抛 `Missing GitHub credentials`），
  Maven Central 查 `g:fan.miuix` 结果为 0；
- 本机工具链是 `aapt`(v1) + `javac` + `d8`，**没有 aapt2/AGP**，而 AAR 的 `0x7f/0x36` 双包资源必须由 aapt2 处理 ID 映射，
  aapt v1 做不到；因此本机只能按 miuix 的设计参数**等价实现**。
- 若要在真机上"完整调用 miuix"，需要一台有 Android SDK 的 PC：把本项目 `app/` 换成 Gradle + AGP 工程，
  依赖 `fan.miuix:*` 并配置 GPR 凭据即可。
