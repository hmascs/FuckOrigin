# FuckOrigin

> **当前版本：0.1.1 beta（功能实验版）**
> 界面很不完善，功能以"能不能跑通"为标准，不保证稳定性与可用性。
> **仅在搭载骁龙 8 至尊版（Snapdragon 8 Elite）+ OriginOS 6（Android 16）的设备上实机使用过**，
> 具体型号为 iQOO Neo10 Pro+（PD2463 / V2463A）；其他芯片平台、其他系统版本一律未验证。
> 同平台的其他 OriginOS 6 机型理论上可参考，但未逐一测试，出问题属正常情况。

OriginOS 的性能与温控实验工具，由两部分组成：

1. **App（LSPosed 模块 + 管理界面）**：把游戏魔盒（`com.vivo.gamecube`）里那些
   "需要条件才生效"的开关放开，并提供频率/温控的手动控制入口。
2. **KernelSU 模块（可选）**：root 侧的频率执行器与温控解除，
   滑块与"信仰模式"依赖它才能真正写进内核。

---

## 0.1 beta 的现状

已经能用的：

- 游戏侧边栏「性能面板」底部注入 CPU / GPU 最低/最高频率滑块 + 保存 + 信仰模式；
- 信仰模式：冻结 thermal-engine、冷却设备归零、频率拉满，退出游戏自动关闭；
- 超分 / 插帧的若干门控放开（Monster+、Q 芯总开关、冲突仲裁、温度源等）；
- 通过根执行器在游戏前台时拉起侧边栏（vivo 自身触发偶发失效时兜底）。

明确不完善的地方：

- 界面风格不统一，部分页面还是纯文本堆叠；
- 侧边栏注入的排版在不同游戏里可能错位，需要按实际容器微调；
- 大量功能只有 hook 放行、没有对应的图形化开关；
- 没有任何自动化测试，全部靠真机手动验证。

## 风险提示

这个项目会修改系统级行为：

- 解除温控意味着**设备可能过热**，"信仰模式"设计上就是奔着温度墙去的；
- 写 CPU/GPU 频率、冻结 thermal-engine 可能导致死机、重启、耗电异常；
- 修改游戏魔盒行为可能让侧边栏、Q 芯专区异常甚至不显示。

**请自行承担风险。** 出问题先卸载模块、回滚设置，必要时重启设备。

## 目录结构

```
app/        Android 应用源码（Java，无 Gradle，用 tools/build.sh 直接编译打包）
app/src/com/fuckorigin/app/xposed/    LSPosed 侧代码（HookEntry / PanelUi）
tools/      构建脚本
module/     KernelSU 模块源码（脚本 + 配置覆盖 + 网页控制台）
docs/       设计与逆向笔记（含大量实测记录与失败过程）
```

## 构建

没有使用 Gradle/AGP，全部靠命令行工具链（`javac` + `d8` + `aapt` + `apksigner`）。
具体步骤见 `tools/build.sh`，需要自备：

- Android SDK platform 的 `android.jar`
- `d8`（r8）与 `apksigner.jar`
- 一个签名用的 keystore（自己生成，不要用别人的）
